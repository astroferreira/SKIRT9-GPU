# z=1 JWST products: 2026-09-09

## Completed observation

The first 1000 x 1000 pixel JWST run completed for TNG50-1 snapshot 50,
subhalo 257247, using the existing halo-mode particle export, 150 kpc field,
and 16-neighbour stellar smoothing lengths. The observer redshift is 1.
A separate unmodified upstream CPU comparison was completed later the same
day; see [the CPU reference report](CPU_REFERENCE_20260909.md). It measures
5.11x end-to-end speedup but also finds flux discrepancies requiring further
investigation, so the current images are not certified CPU-equivalent.

Output directory:

```
/home/astroferrreira/SKIRT/benchmarks/z1_jwst_20260905/run_1k_10m_recovery_20260909
```

Open `products/index.html` for the gallery, science FITS links, spectra, and
validation metadata. The four views are xy, xz, yz, and oct.

- Eight NIRCam broadband filters and nine MIRI filters in each image cube.
- 10 million primary and 10 million secondary packets.
- Stochastic dust emission, 400-point radiation field, 1000-point dust grid.
- High-resolution Bruzual-Charlot templates plus the original MAPPINGS source.
- 4051 spectral samples over observer wavelengths 0.7-5.3 micron.
- RGBs use asinh stretch 30. NIRCam R/G/B = F444W/F277W/F115W;
  MIRI R/G/B = F2100W/F1500W/F770W. They are false-colour displays.
- Spectrum display uses an ideal constant-R=1000 Gaussian, not a calibrated
  NIRSpec line-spread function. Native template resolution limits remain.

No telescope PSF, detector noise, slit losses, or velocity broadening was
applied. FITS pixels are unchanged by rendering. All 17 bands in all four
cubes were checked for expected dimensions, finite nonnegative values,
positive total signal, and matching filter pivot wavelengths. The RGBs and
spectrum were visually inspected. Four convolution unit tests pass.

**These are first-pass products, not a noise-converged observation.** The
simulation also reports dust-optics coverage ending at 1000 micron, while
its combined required wavelength range extends to approximately 2020 micron.
The warning is retained in the log, gallery, and product metadata; it must
be resolved or quantified before precision scientific use.

## Remaining goal work

- Establish the current 500x CPU/GPU target with genuinely comparable runs.
  The earlier `skirtgpu` invocation without `-g` was still GPU-enabled and
  must not be used as a CPU baseline.
- Bound source-table memory for large, high-resolution galaxies without
  relying on disabling GPU source caching.
- Continue accelerating primary source preparation and photon transport;
  stochastic dust preparation now has the validated GPU path described below.
- Determine packet counts from independently seeded observations at multiple
  counts, evaluated at the intended spatial and spectral resolution.
  The starting estimate is `N_target = N_pilot * (noise_pilot / noise_target)^2`,
  but its scaling must be checked. Zero-hit faint regions are not converged;
  repeatability of identical seeds is not an independent noise measurement.
- Quantify noise and the dust wavelength-coverage warning before treating the
  current FITS cubes or spectrum as precision science products.

The overall acceleration and optimal-packet-count goal remains open. A
genuine CPU baseline now exists, but it falls well short of the target and
does not establish whole-workflow numerical parity.

## GPU stochastic dust update

A custom CUDA kernel now implements the existing stochastic dust calculation
in batches of at most 256 cells, using both GPUs. It preserves the CPU grain
tables, temperature-grid selection, equilibrium mass shortcuts, CMB term, and
probability normalization. It uses triangular transition-matrix scratch space
bounded at about 2.14 GiB per GPU for the current maximum temperature grid,
plus cached grain tables and small batch input/output arrays. Scratch storage
does not grow with the total number of galaxy cells.

This path is enabled by default for eligible single-medium, constant-mix,
Voronoi-grid stochastic dust source preparation. Unsupported cases retain
the scalar implementation. `SKIRTGPU_STOCHASTIC_DUST=0` disables it;
`SKIRTGPU_VALIDATE_DUST_EMISSION=1` enables scalar reference checks and turns
unavailability or numerical mismatches into errors instead of accepting fallback.
The original scalar emissivity equations were not modified.

Two completed runs use exactly the original physical configuration and packet
count, with seeds 12345 and 67890:

| Result | Seed 12345 | Seed 67890 |
| --- | ---: | ---: |
| Whole simulation | 174 s | 181 s |
| Primary emission | 94 s | 96 s |
| Dust preparation | approximately 21 s | approximately 21 s |
| GPU dust cells | 343,503 | 343,503 |
| CPU fallback cells | 0 | 0 |
| Scalar-checked cells | 2,684 | 2,684 |
| Maximum normalized emissivity error | 8.25e-15 | 5.52e-15 |
| Peak host memory, SKIRT-reported | 15.4 GB | 15.5 GB |

The second run exercised default enablement, progress reporting, and zero-field
plus radiation-field scaling checks from 1e-8 through 1e8. Those additional
checks agreed within 4.33e-15. The error metric divides by the larger of the
reference wavelength emissivity and 1e-12 times its spectrum's peak. The
validation threshold is 1e-6. The current model has CMB heating disabled, so
CMB-enabled equivalence is not established by these two runs.

Each contains a complete log, FITS cubes, raw spectra, and a `products/` gallery.

all large-galaxy memory requirements. High-resolution primary source caching
also remains disabled for these runs.

## Initial packet-count estimate

`tools/estimate_jwst_packet_noise.py` checks completed runs, distinct seeds, and
matching physical configurations before measuring ensemble variance. It
corrects the signal-power estimate for noise in the reference mean, evaluates
fixed radial regions at 150 pc, 600 pc, and 1.2 kpc spatial sampling, and uses
ideal R=1000 smoothing for the spectra. It does not infer convergence from
identical images, zero-hit pixels, or noise-dominated regions.

The two-seed result is `packet_noise_10m_two_seeds.json` under the benchmark root.
For a provisional 1% region-RMS target, the integrated spectral windows suggest
approximately 74-120 million packets per phase. The worst full-field image band
is F070W: approximately 15.8 billion at native pixels, 1.16 billion after 4x4
binning, or 496 million after 8x8 binning. Binning sacrifices spatial resolution;
these numbers do not justify replacing the requested images with blurred ones.
Faint outer regions can demand much larger counts or a stronger pilot.

These are extrapolations from only two equal-count seeds, not recommended final
counts or a demonstrated optimum. The metric is a signal-weighted region RMS,
not a bound on every faint pixel's noise. At least four seeds, a second count,
and an explicit observational resolution/brightness criterion remain necessary
to test the assumed inverse-square-root scaling and finalize packet allocation.

## Experimental spectral-table compaction

`SKIRTGPU_COMPACT_DUST_SPECTRA=1` stores PDF/CDF rows only for cells assigned
packet histories. It retains all geometry and original entity ordering,
including non-emitting absorbing cells used in column-density bounds. An
indirection table maps entities to spectral rows without changing the
entity-based GPU random-state hash. Invalid active-cell mappings are rejected.
The option is **off by default pending deterministic validation**.

The trial `run_1k_10m_compact_seed67890` completed in 175 s and reported
9.61 GB peak host memory, versus 15.5 GB with dense spectral tables.
Its 343,503 spectral rows occupy 2,753,520,048 bytes per PDF/CDF pair,
plus 4,604,028 bytes for the row map, instead of 1,151,007 full rows.
Scalar dust checks still passed, but `compact_dust_regression.json` failed
the strict same-seed pixel comparison against the prior hybrid observation.

The upstream worker-thread RNG is intentionally nondeterministic, so these
hybrid runs are not expected to be pixel-identical even with matching seed
properties. That makes this comparison insufficient to prove or rule out
a compaction regression. A deterministic dust-launch comparison is still
required before promoting the option. `tools/compare_jwst_runs.py` provides
strict image/spectrum regression metrics for reproducible launch paths;
it is not a Monte Carlo equivalence or convergence test. The helper suite
has 16 passing unit tests, and the CUDA self-test covers compact mapping
bounds and empty history ranges.
