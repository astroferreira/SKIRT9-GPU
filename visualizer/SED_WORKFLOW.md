# NIRSpec and MIRI integrated SEDs

In the running Observatory at <http://127.0.0.1:8765>, check **Integrated SED**
under **Instruments**. Choose a NIRSpec or MIRI spectral mode, viewing direction
and photon budget, then run the observation.

For an SED-only request, the worker creates a separate `.ski` containing exactly
**one `SEDInstrument`** and **no `FrameInstrument` or broadband grid**. If the
broadband or RGB checkboxes are also selected, those frame instruments are added
to the same `.ski` and all products are generated by one SKIRT run. It preserves the selected base
model's source spectra (including the current BPASS/TODDLERS models), medium,
dust physics, heating/emission grids, cosmology and iteration settings. Image
dimensions and image FOV do not add a detector or crop the spectrum. Source
selection, model setup, dust heating and transport still run, so an SED-only
request can still take time on a large galaxy.

## Geometry and spectral frame

The instrument uses the camera's **inclination and azimuth** and the dataset's
observer distance. `radius="0 pc"` means the complete spatially integrated
model, including any companions present in the input catalogues. The interface
disables image FOV, target offsets and roll in this mode and hides the image
FOV guide. A new direction produces a new observation; changing only image
parameters reuses an existing matching SED.

For a cosmological observer (`distance=0` and positive redshift), preset
wavelengths are in the **observer frame**. A positive fixed distance retains
SKIRT's **rest-frame** convention. The selected convention is shown in the
controls, plot, JSON and FITS. The output is total **λFλ in W/m²**, not surface
brightness, detector counts or an aperture-corrected IFU extraction.

## Spectral modes

The **SED resolving power · R** field accepts integers from **10 to 10,000**.
Changing the spectral mode fills its default R; **Preset R** restores that value.
Custom R keeps the preset wavelength coverage but changes the SKIRT SED grid
to two samples per resolution element and changes the separately saved ideal
Gaussian convolution to the requested R = λ/Δλ. The interface shows the expected
sample count. This is an idealized constant-R observation, not a calibration of
the instrument's actual resolving power. Higher R cannot recover detail absent
from the source templates or dust-emission grid, and may require more photons.

The selected value is saved in requests, manifests, spectral JSON, and the FITS
`RESPOWER` header; history restores it and marks changed R as a different view.
Existing preset-default SEDs remain reusable, including when their default R is
entered explicitly. Image requests ignore the SED resolution field. The API
uses optional integer `spectral_resolution`; omitted or null uses the preset.

NIRSpec ranges and representative resolving powers follow the
[STScI disperser/filter table](https://jwst-docs.stsci.edu/jwst-near-infrared-spectrograph/nirspec-instrumentation/nirspec-dispersers-and-filters).
MIRI LRS uses the documented 5–14 μm nominal range and R≈100 at 7.5 μm, although
its real resolving power varies with wavelength and calibration beyond 12 μm
has limitations. See [MIRI LRS documentation](https://jwst-docs.stsci.edu/jwst-mid-infrared-instrument/miri-observing-modes/miri-low-resolution-spectroscopy).
MIRI MRS uses the combined 4.9–27.9 μm range; R=3000 is an explicit representative
approximation to its wavelength-dependent R≈1500–3500, not a calibrated channel
response. See [STScI's IFU overview](https://jwst-docs.stsci.edu/methods-and-roadmaps/jwst-integral-field-spectroscopy).

These are **idealized integrated spectra**, not a full NIRSpec or MIRI instrument
simulator. There is no grating throughput, variable LSF, detector gap, detector
noise, slit throughput, PSF or IFU geometry. Instrument names identify wavelength
and nominal resolution presets. There is no stitching of actual MRS exposures.
Native stellar/cloud templates and the model's dust-emission grid can have
coarser spectral structure than the requested sampling; a high R setting does
not recover absent information. Physics/template warnings remain in the model
metadata and execution log.

## Raw and convolved products

The `ResolutionWavelengthGrid` samples twice per nominal resolution element,
using SKIRT's logarithmic grid. The postprocessor verifies the exact expected
number of bins, positive/increasing wavelengths, matching range, declared
micron and W/m² units, and finite/nonnegative fluxes. A blank spectrum is
explicitly flagged.

A Gaussian is then applied to λFλ on the log-wavelength grid, with
σ = 1/(R √(8 ln 2) Δlnλ). This follows the existing JWST observation helper's
constant-R convention. Edge values are extended; the kernel is truncated at
four sigma. Raw spectral samples are never overwritten. The instrument's
finite bins and the templates already have their own resolution, so the
effective final resolution is not guaranteed to equal the ideal Gaussian R.

Each job retains:

- `observation_spectrum_sed.dat`: original SKIRT SED, unchanged.
- `spectrum.fits`: binary table with `WAVELENGTH` (μm),
  `LAMBDA_FLAMBDA_RAW` and `LAMBDA_FLAMBDA_SMOOTHED` (W/m²); headers identify
  the frame, aperture, preset and ideal resolving power.
- `spectrum.csv`: the same three quantities with explicit units in column names.
- `spectrum.json`: both curves, metadata and original SKIRT column headers.
- `spectrum.png`: standalone logarithmic plot with raw and convolved curves.
- `observation.ski`, `manifest.json` and execution logs: the exact model,
  input identities, direction, preset and runtime evidence.

The browser shows a plot thumbnail and a larger interactive spectrum. Hover
for numerical values, drag horizontally to zoom, select log/linear flux, show
the raw curve, or reset the zoom. Both image and SED jobs use the existing queue,
loading/cancel controls and persistent observation history. Restoring an SED
selects its observing mode, direction and photon budget.

Existing image cache identities are preserved. SED cache identities include
the preset definition and direction, and exclude unused image filters,
dimensions, FOV, pan and roll. Changes to input/model/binary identities still
invalidate reuse.

## Tests

```bash
.venv/bin/python -m pytest tests/test_pipeline.py tests/test_spectra.py -q
npm test
SKIRT_VIEWER_REAL_SED=1 npm run test:browser -- tests/browser/spectra.spec.js
```

The last command opts into actual NIRSpec PRISM and MIRI MRS GPU runs using the
current default AREPO catalogue and a one-million-packet preview budget. It
checks that each configuration has only one SED observer and no frame, that
all spectral downloads work, and that the interactive chart, caching and
history restoration work. It reuses already-completed matching results when
available. Run without `SKIRT_VIEWER_REAL_SED=1` for control-only browser checks.

New unit checks cover all 11 configurations, preservation of model physics,
units/shapes, unchanged raw spectra, FITS/CSV consistency, Gaussian normalization,
blank/invalid spectra, SED cache semantics, API downloads and restart persistence.

## Verified local runs — 2026-09-10

Two actual runs were submitted through the browser, not through the fake test
worker. Both used AREPO Galaxy 095, inclination 55°, azimuth 35°, observer z=1,
seed 12345 and the **Preview · 1M** packet budget per phase. The existing
BPASS/TODDLERS, DraineLi stochastic dust and iterative dust self-absorption
configuration was retained.

| Mode | Saved job | End-to-end time | Valid positive samples |
| --- | --- | ---: | ---: |
| NIRSpec PRISM | `d7a68ab83d1942ccab5e1875a01023bf` | 247.00 s | 438 / 438 |
| MIRI MRS | `958a3df1ca0b45c082258c203fb84e77` | 250.15 s | 10,439 / 10,439 |

Artifacts are under `var/jobs/<job-id>/`. Each generated configuration contains
one `SEDInstrument`, no frame instrument, and no image FITS output. The execution
logs explicitly confirm two NVIDIA RTX 5090 CUDA devices. This remains SKIRTGPU's
hybrid execution path; GPU activation is not a CPU-parity or speedup benchmark.

For both runs, native wavelength and flux samples match the FITS table and JSON
raw arrays exactly. Wavelength endpoints match the selected preset, all fluxes
are finite and positive, and download/API checks passed. The browser checks
also exercised hover readouts, zoom, log/linear flux, raw overlays, cache reuse,
history restoration and a 390-pixel mobile viewport without page overflow.

Both simulations reached the model's dust-iteration convergence criterion after
five iterations (absorbed-secondary luminosity changes of 1.86% and 1.70%,
respectively, below the configured 3%). This does **not** establish spectral
Monte Carlo convergence: the high-resolution MIRI preview is visibly noisy and
may need a higher photon budget. Both logs retain the existing BPASS wavelength
coverage warning: the template stops at 160 μm while the configured source range
extends to 2000 μm. No attempt was made to silently change this model setting.

The Python suite passed **41 tests**, with two dependency deprecation warnings;
the camera suite passed **2 tests**. The initial SED browser run passed both
tests in 8.4 minutes. Restarting the service retained all 12 existing images and
both new SEDs as completed observations. The post-restart browser suite passed
all four enabled checks in 10.2 seconds, reusing the two SEDs; the opt-in
expensive image-render test was skipped.
